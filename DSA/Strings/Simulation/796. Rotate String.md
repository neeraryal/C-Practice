# 796. Rotate String
> Kya `s` ko kuch baar left-shift (pehla char end pe) karke `goal` ban sakta hai?

| Pattern | Data structure | Time | Space |
|---|---|---|---|
| [Simulation – `s+s` rotation trick](simulation.md) | `string temp = goal+goal` | O(n²) worst (naive `find`) | O(n) |

**How it works**
- **Soch:** Har shift ko simulate karna (n shifts × n compare) bhi O(n²) hai aur code lamba. Observation: `s+s` mein `s` ki **har** rotation substring ki tarah baithi hai (`"abcde"+"abcde"` mein `"cdeab"` index 2 se). To bas ek substring search.
- **Length check:** Length alag → rotation possible hi nahi.
- **Search:** User ne ulta kiya: `temp = goal+goal`, phir `temp.find(s)`. Equivalent hai — `goal`, `s` ki rotation hai ⇔ `s`, `goal` ki rotation hai (k left-shift ka ulta = n−k left-shift).
- **Kyun sahi hai:** `goal+goal` ke length-n substrings exactly `goal` ki n rotations hain. Same length + substring mila ⇔ rotation. `find` naive worst O(n²), par n ≤ 100.
- **Dry run:** `s="abcde", goal="cdeab"`
  - lengths same (5)
  - `temp = "cdeabcdeab"`
  - `temp.find("abcde")` → index 3 → true ✔

**Gotcha:** Length check ke bina chhoti string `s+s` mein hamesha mil jaati — `s="aa", goal="a"` → `"aa".find("aa")` → galat `true`.
**vs related:** [1903](<1903. Largest Odd Number in String.md>) / [8](<8. String to Integer (atoi).md>) char-by-char scan karte hain; yahan ek string identity (`s+s`) poora simulation hata deti hai.
**Better approach:** `find` ki jagah KMP / Z-algorithm → worst case bhi O(n).

## Code

```cpp
class Solution {
public:
    bool rotateString(string s, string goal) 
    {
        if (s.size() != goal.size())  // length alag → rotation nahi; warna chhoti string s+s mein mil jaati
            return false;

        string temp= goal+goal;  // goal ki saari n rotations iske length-n substrings hain
        return temp.find(s) != string::npos;  // s mila ⇔ s, goal ki rotation (aur ulta bhi)
    }
};
```
